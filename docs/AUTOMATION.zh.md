# 自动化：换代、每小时自检、DSH 子智能体怎么跑

这一页讲的是**运行期的自动化**——它决定了「一个会回话的 bot」和「一个自己维持自己的角色」之间的差别：
每天的会话换代、每日记忆整理、每小时自检，以及怎么用 DSH Agent Teams（一个 Lead 会话 + 若干子智能体）把它们跑起来。

只装引擎、接上 QQ 的话，这些**都还不会跑**。搭起来不贵，但要不要搭决定了她像不像长期活着的人。

---

## 一、哪些事自动跑、谁在跑

| 时间（本地） | 做什么 | 跑在哪 | 动到什么 |
|---|---|---|---|
| **04:00** | 换代——每个聊天换一个全新的 DSH 会话 | **bridge.js** | `state/session-rotate.json`、记忆卡、首轮事件 |
| **05:30** | 记忆整理——把前一天的聊天压成 2–5 条具体事件 | **bridge.js** | `memory-inbox.jsonl` → `memory-card.json` → 注入文本 |
| **每小时整点** | 自检——服务、行为筛查、规则小修、注入审计 | **DSH 定时任务** | `state/selfcheck*.json`、`bridge.log`、筛查脚本 |
| **08:00** | 早报——夜间体检、连续性检查、规则大整理、记忆库体检 | **DSH 定时任务** | `nightly-audit/`、`rules-audit`、`memory-db-audit` |
| **22:00** | 三句话日报发给主人 | **DSH 定时任务** | 工作日志 + 主人通知通道 |

这里有两个不同的宿主，排查问题时要分清：

- **换代和整理跑在 `bridge.js` 里**：只要桥接进程活着，DSH 关了它们也照跑。它们只写文件，不发消息。
- **自检 / 早报 / 日报是 DSH 的 `schedule` 定时任务**：绑在创建它的那个会话上，会唤醒那个会话；
  会话被删、任务被删，它们就没了。

## 二、DSH 这边怎么搭

### 方案 A：一个会话 + 三条提醒（最简单）

1. 开一个 DSH 会话，把它当「值班会话」（本项目的叫法是 PM）。
2. 用 `schedule_create` 建三条提醒：
   - `cron { expression: "0 * * * *" }` —— 每小时自检
   - `daily { time: "08:00:00" }` —— 早报
   - `daily { time: "22:00:00" }` —— 日报
3. **具体步骤写在文件里，不写在提醒里**。提醒正文只有一句：
   「读 `pm/runbooks/hourly-selfcheck.md` 并按它执行」。以后改文件，不改日程。

为什么用文件：提醒正文在创建时就冻住了，而值班手册每周都在变；
把整套流程塞进 30 行提醒里，两天就过期了。

### 方案 B：DSH Agent Teams（Lead + 子智能体）

Lead 会话拿走所有日程和所有对主人的决策；子智能体是**干活的人，不是工位**：

- 常见分工：`duty`（服务/日程）、`bugfix`（行为/桥接故障）、`mechanism`（情绪/驱力/规则）、
  `memory`（记忆卡/主题/检索）、`tools`（房间/语音/B站）、`accounting`（token/花费）。
- Lead 先建共享任务（`team_task_*`）并写清 **write scope**，再用 `send_message` 叫醒负责人。
  一个文件只有一个写手。
- 上限 8 人（含 Lead），名字永久占用；只开真需要的。

**子智能体做不到的事**：它们不能持有日程。被委派的会话调用提醒工具会得到
`{"code":"subagent_session","message":"A delegated subagent cannot use reminders."}`——这是设计如此。
所以 **Lead 管钟，子智能体管手**。

**叫醒方式**：子智能体干完一轮就会闲置，它不会自己轮询；Lead 发消息把它叫醒。
长任务要求它在返回前写一份 `inflight.md`（做到哪 / 下一步的确切命令 / 怎么算做完），
Lead 再决定要不要接着叫。

### 成本提示

每个子智能体都是一个带独立上下文的完整会话。两个做只读审计的并行子智能体通常值；
六个常驻的基本不值。**先一个会话，等某类活反复出现再加人。**

## 三、数据流：谁写什么

```
QQ 消息 ──▶ 桥接：追加到 memory-inbox.jsonl
                  │
       05:30 整理 │（桥接）
                  ▼
           memory-card.json ──▶ 插件宿主渲染注入文本
                  │                      │
                  ▼                      ▼
        主题页（memory/topics/）    prompt-qq.md / prompt-qq-group.md
                  │
                  ▼
        桥接在唤醒时把渲染好的文本注入

PM 会话（DSH）：只读 state 文件，写工作日志 / 值班手册 / 任务板，
                不写记忆卡。
```

几条能让它长期不乱的规矩：

- **一个文件一个写手。** 桥接写记忆卡、插件宿主渲染注入文本、PM 会话只读。
  真要让两个进程写同一个文件，加一道便宜的保护——本仓库的做法是写之前比一次文件修改时间，
  变了就重读合并。
- **备份不是数据库。** 数据库是全量档案（`memory-card-full.jsonl`）；带时间戳的副本只是后悔药。
  `scripts/memory-db-audit.mjs` 用一条只读命令证明档案完整、备份只是冗余。
- **整理窗口要写死。** 05:30 那条整理写的是「昨天 00:00 → 今天 00:00」，
  不能拿「今天」当昨天事件的标签（本项目真踩过这个坑）。

## 四、每小时自检到底做什么

1. **服务健康**：桥接端口、DSH 就绪、TTS、QQ 网关。能修的修；QQ 网关容器不要随手重启（会掉登录）。
2. **行为筛查**：看最近 2 小时的群/私聊，找四类——私聊内容被当群谈资（隐私）、
   明明记得却说不记得、人名/数字/群搞错、情绪值贴边。只报确认过的，不报猜测。
3. **规则小修**：只清乱码和明显重复，每小时最多 2 条，改前备份。
   大整理是 08:00 的活，小时段不能变成重写会话。
4. **注入审计**：读**真实投递的** prompt（不是预览），报「静默截断」。
   静默截断是 bug，设计内裁剪不是。
5. **盯防清单前 5 项**：主人反复问过的那批问题，各看一眼，一行一条。
6. **写一行日志就停**。不是 P0 不发消息。安静的一小时就是成功的一小时。

## 五、换代细节

- `state/session-rotate.json` 存日期。桥接在 04:00 之后只换一次，同一天重启也不会重复换。
- 换代给每个会话一个干净的新 DSH 会话。**记忆卡、主题、目标、情绪、日记都还在**，
  消失的只有原始对话。
- 换代后的第一轮会带一条 48 小时内的真实事件（首轮事件层），她不会醒来两眼一黑。
- 早报要核对四件事：所有会话都换了、首轮事件注入了、整理写了 N 条、主题索引重建了。

## 六、运营纪律（踩坑换来的）

- **报警分级**：P0 = 服务挂 / 隐私泄漏 / 数据丢（立刻）；P1 = 任务失败、需要拍板（当轮/一小时内）；
  P2 = 收进日报。主动汇报一天 ≤6 条（P0 不算）。
- **夜里安静**：00:00–07:00 的非 P0 攒到 08:00 一起说。
- **重启纪律**：桥接重启是日常（备份 → `node --check` → 重启 → 验证）；
  DSH 重启会换掉所有会话，要先告知、把手上写操作落盘、再重启。
- **不要热改桥接**：备份、打补丁、语法检查、重启、验证、留回滚方案，缺一不可。
- **密钥只放 `config.json`**，永远不要提交。`docs/PRIVACY.md` 里的剥离审计是给分发用的，不是给自己部署用的。
- **成本量级**：一次唤醒就是一次完整 prompt；每小时自检一轮几千 token。
  嫌贵就改成每 2–3 小时一次——桥接侧的换代和整理不受影响，照跑。

---

## 七、最小搭建清单

1. 装引擎、写 `config.json`（主人 QQ、允许的群）。
2. 确认桥接能起：`node src/bridge.js` → 控制台 `:3100` → `dshReady: true`。
3. 开一个值班会话，建三条提醒（每小时 / 08:00 / 22:00）。
4. 建 `pm/runbooks/` 目录，写三份手册（自检、早报、日报）。
5. 可选：开 4–6 个子智能体，命名分工，用共享任务板。
6. 手动跑一次自检、读一遍输出；然后等第一次定时触发。
7. 观察第一个完整的夜晚：04:00 换代、05:30 整理、08:00 早报。

本页的假设：桥接和 DSH 在同一台机器上；DSH web 端口变化时桥接会自动重连；
日程绑在创建它的会话上。
